# Pilot: LELA on two paragraphs of late-antique history

Question: how well does [LELA](https://github.com/dig-team/LELA) detect and link named entities in history text?
Two paragraphs (one per paper), 35 hand-annotated mentions, linked to YAGO 4.5, 12 LELA configurations.
Results: `results/summary.md` (table) and `results/<config>.json` (numbers and every error).

Tested with LELA commit `0202b81` (17 Aug 2026), Windows, Python 3.12.

## Files

| File | What it is |
| --- | --- |
| `make_pilot.py` | annotation table -> `gold.json`, the two paragraphs (`texts/`) and LELA's input (`lela_in/`) |
| `gold.json` | 35 mentions: position in the paragraph, text, YAGO id (or `null` = no entity in YAGO) |
| `configs/` | the 12 LELA configurations; Groq ones hold `__KEY__` instead of a key |
| `run_lela.py` | runs `lela.cli` and retries when the LLM API answers 429 (LELA does not) |
| `score.py` | compares `pred/<config>/` with `gold.json`, writes `results/` |

Not in the repository: the paper text (`texts/`, `pilot/texts/`, `pilot/lela_in/`) and LELA's raw output (`pred/`),
which quotes the papers. All of them are regenerated by the steps below.

## Repeat it

1. **Clean text** (needs the two PDFs in `papers/`): `uv run python prepare/prepare_texts.py`
2. **Pilot inputs and gold:** `python pilot/make_pilot.py`
3. **LELA:** clone it, then `uv sync` inside the clone (a GPU run needs a CUDA build of PyTorch, see below).
   The first run downloads YAGO 4.5 (145 MB zip, about 650 MB unpacked) and, for GLiNER configs, the NER model
   (`numind/NuNER_Zero-span`, about 1.8 GB).
4. **Run a configuration** from the LELA folder, once per paper (LELA takes one file at a time):
   ```bash
   P=<path to this repo>/pilot
   for d in alford2026 nechaeva2017; do
     python $P/run_lela.py --config $P/configs/gliner_fuzzy.json --input $P/lela_in/$d.txt --output $P/pred/gliner_fuzzy/$d.jsonl
   done
   ```
   For the LLM configs, put the key into a temporary copy and delete it afterwards, never into the repository:
   ```bash
   sed "s/__KEY__/$GROQ_API_KEY/" $P/configs/gliner_fuzzy_groq120b.json > /tmp/cfg.json   # then pass /tmp/cfg.json
   ```
5. **Score:** from the repo root, `python pilot/score.py quickstart gliner_fuzzy gliner_fuzzy_groq120b ...`

## Configurations

| Config | NER | Candidates | Final choice |
| --- | --- | --- | --- |
| `quickstart` | regex | fuzzy, 10 | first |
| `gliner_bm25` | GLiNER | BM25, 10 | first |
| `gliner_fuzzy` | GLiNER | fuzzy, 20 | first |
| `gliner_fuzzy_groq120b` / `_groq20b` / `_qwen27b` | GLiNER | fuzzy, 20 | LLM on Groq: gpt-oss-120b / gpt-oss-20b / qwen3.8-27b |
| `ner_ext_t05` / `ner_ext_t03` | GLiNER, extended types, threshold 0.5 / 0.3 | fuzzy, 20 | first |
| `ner_ext_t03_k64` | as `ner_ext_t03` | fuzzy, 64 | first |
| `ner_ext_t03_ce` | as `ner_ext_t03` | fuzzy, 20 | cross-encoder (top 10), then first |
| `ner_ext_t03_groq120b` / `ner_ext_t03_k64_groq120b` | as `ner_ext_t03` | fuzzy, 20 / 64 | gpt-oss-120b |

## Notes

* **GPU.** The cross-encoder is loaded in float16 and is far too slow on a CPU (it did not finish in 76 minutes).
  Install a CUDA build in a separate environment, for example
  `UV_PROJECT_ENVIRONMENT=.venv-gpu uv sync --frozen` and then
  `uv pip install --python .venv-gpu/Scripts/python.exe --reinstall --no-deps torch==2.13.0 --index-url https://download.pytorch.org/whl/cu126`.
  With an RTX 2050 the whole run took about 7 minutes.
* **Dense retrieval was not run:** embedding all 5.8 million YAGO entities is out of reach on one machine.
* **Metrics** (`score.py`): *mention* = predicted span equals a gold span exactly; *link* = span and YAGO id both
  right (a link on a gold `null` mention is an error); *candidates* = the gold entity is among LELA's candidates;
  *no entity* = mentions with gold `null` that LELA left unlinked.
* **Gold status:** a draft by one annotator, not yet reviewed by a historian; the open decisions (Persia, Romans,
  Syria, Khuzestan, Isidore, Hermes, History of the Armenians, Vahan Mamikonean) are listed in the decision table of the pilot report (shared separately).
* Two paragraphs are too few to rank configurations; read the numbers as an illustration of where LELA fails.
